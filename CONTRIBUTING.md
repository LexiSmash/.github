# Contributing to the LexiSmash organization

This file is the **default** contributing guide for any repository under the LexiSmash GitHub organization that doesn't have its own. If the repository you want to contribute to already has its own `CONTRIBUTING.md` (for example [LexiSmash_dictionaries](https://github.com/LexiSmash/LexiSmash_dictionaries), which has repo-specific rules for dictionary corrections), follow that one instead — it's more specific and takes precedence.

## Before you start

- Please read our [Code of Conduct](CODE_OF_CONDUCT.md) — participation in any repository of this organization means agreeing to follow it.
- One Pull Request per reason for change is much easier to review than one large PR bundling several unrelated changes — it's also more likely to be merged quickly.
- Every Pull Request is reviewed **by hand** by a human maintainer before being accepted — don't expect an automatic or instant merge.

## Opening an Issue

Search existing Issues first, to avoid duplicates. When opening a new one, describe what's wrong (or what you'd like to see) as clearly as you can — steps to reproduce, screenshots, or a short rationale all help it get triaged faster.

## Opening a Pull Request

1. Fork the repository and create your branch from the default branch.
2. Make your change, keeping it focused on a single reason.
3. Explain **why** the change is needed in the PR description, not just what it changes.
4. Make sure any existing checks for that repository still pass.

## Found a security issue instead?

Please don't open a public Issue or Pull Request for a security vulnerability — see our [Security Policy](SECURITY.md) for how to report it privately.
